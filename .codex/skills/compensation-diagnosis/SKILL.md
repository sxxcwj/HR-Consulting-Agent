# 企业薪酬诊断 Skill

## 目的与边界

使用本 Skill 选择并组织专业、证据导向的薪酬诊断流程。本 Skill 定义诊断方法，不计算薪酬指标；需要计算时调用实际可用的 Analysis Tool，由 HR Consultant 解释工具返回的事实。

严格分离三类职责：

- **Skill**：选择诊断问题、证据范围、假设顺序和验证路径；
- **Tool**：读取允许使用的数据或执行确定性计算；
- **Agent**：区分证据类型、解释结果、控制判断边界并提出行动建议。

遵守 `PRODUCT_SPEC.md`、`AGENT_SPEC.md` 和 `WORKFLOW.md`。不要新增一级输出格式，不要填补缺失数据，不要声称拥有尚未取得的市场资料，不要替企业作出个人调薪决定。

## 何时使用（When to use）

当用户需要“诊断”而不只是单一计算时使用，包括：

- 员工认为工资不公平或出现同岗不同薪争议；
- 新老员工、上下级或不同职级之间疑似薪酬倒挂；
- 需要分析内部公平性、外部竞争力、岗位或职级薪酬差异；
- 需要分析薪酬压缩、薪酬带宽重叠或固定与浮动薪酬结构；
- 需要检查绩效—薪酬、职业发展—薪酬之间的关系；
- 需要判断薪酬激励是否符合岗位特点；
- 不知道调薪应从哪里开始，或需要优化薪酬体系；
- 怀疑离职与薪酬有关，但尚需进一步验证；
- 用户明确希望进行企业薪酬诊断。

## 不应使用（Do not use）

以下任务不要自动使用完整薪酬诊断流程：

- 只询问某一个工资数字或解释“薪酬”概念；
- 只计算平均值、中位数、最小值、最大值等已有指标；
- 只读取 Excel 字段、Sheet、缺失值或预览；
- 不含薪酬诊断目标的纯绩效、纯招聘或纯劳动法问题；
- 非 HR 请求。

基础计算优先使用对应 Tool。用户进一步追问计算结果对公平性、竞争力、倒挂、结构或调薪意味着什么时，再使用本 Skill。

## 诊断目标

按照以下链路工作：

`明确诊断对象 → 确认数据口径 → 识别问题表现 → 选择诊断维度 → 获取证据 → 建立 2—4 个假设 → 验证假设 → 形成分层建议`

目标不是立即回答“工资高不高”或“薪酬公平不公平”，而是说明：当前能得出什么、不能得出什么，以及怎样取得足以支持管理决策的证据。

## 证据纪律

在语义上严格区分以下类型，不要求机械打印所有标签：

- **FACT**：用户在本轮明确提供、可以直接使用的事实；
- **USER_CLAIM**：用户或员工的观点，例如“大家都觉得工资不公平”；
- **DATA_FACT**：实际执行 Tool 后返回的统计事实；
- **DOCUMENT_FACT**：本轮实际读取的企业文件直接支持的规定；
- **HYPOTHESIS**：有待验证的可能解释；
- **RECOMMENDATION**：有适用前提的管理建议，不是事实结论。

不得把差异直接升级为不公平，把相关性写成因果，把制度规定写成实际执行，或把员工抱怨写成已证实的薪酬体系缺陷。

## Step 1：明确薪酬问题

识别主要诊断问题，只选择回答当前问题所必需的维度：

1. **Internal Equity｜内部公平性**：企业内部可比工作、责任与薪酬的关系；
2. **External Competitiveness｜外部竞争力**：企业薪酬与相关劳动力市场基准的关系；
3. **Pay Structure｜薪酬结构**：固定工资、浮动薪酬、奖金、津贴和总现金收入；
4. **Pay Compression｜薪酬压缩**：相邻职级或经验群体的薪酬差距过小；
5. **Salary Inversion｜薪酬倒挂**：较低职级、下级或新入职的可比对象薪酬更高；
6. **Performance-Pay Link｜绩效薪酬联动**：绩效结果与薪酬结果是否形成可验证联系；
7. **Career-Pay Link｜职级薪酬关系**：岗位范围、职级晋升与薪酬增长是否衔接；
8. **Incentive Effectiveness｜激励有效性**：激励设计是否支持预期岗位行为；
9. **Salary Adjustment｜调薪机制**：调整优先级、规则、治理和实施条件。

不要把所有维度机械混在一起。明确一个主要问题，只保留实质影响判断的次要问题。

## Step 2：确认范围和比较口径

确认足以回答问题的最小范围：

- 企业、业务单元、部门、岗位、岗位序列和职级；
- 人员范围及记录是否具有可比性；
- 薪酬周期和数据生效日期；
- 固定工资、浮动薪酬、奖金、津贴、总现金收入及币种；
- 入职时间、司龄、岗位任职年限、绩效和调薪记录；
- 地区、用工类型、工时制度和重要职责差异；
- 用户最终需要支持的管理决策。

不得在未换算或未说明限制时比较月度固定工资与年度总现金收入、不同币种、不同周期或职责明显不同的岗位。口径缺失时，说明它阻断了哪一项结论。

尽量使用匿名员工编号和聚合结果。不要索取或复述不必要的姓名、身份证号、联系方式、医疗信息、投诉记录等个人信息。

## Step 3：区分问题表现与结论

先描述可观察表现，再提出原因。例如：可比群体内部薪酬分散、相邻职级区分度弱、新员工薪酬高于老员工，或持续出现薪酬投诉。

注意：

- “员工不满意”是 USER_CLAIM，除非已明确样本、来源和频率；
- “A 部门平均薪酬高于 B 部门”只能是 FACT 或 DATA_FACT；
- “A 部门薪酬不公平”属于 MANAGEMENT CONCLUSION，需要岗位、职级、地区、绩效等解释变量支持。

## Step 4：诊断内部公平性

只比较具有合理可比性的群体，并检查能够解释差异的因素：

- 岗位、岗位序列和职级；
- 管理层级、职责范围和岗位价值；
- 部门与工作地区；
- 入职时间、司龄和岗位任职年限；
- 持续绩效和稀缺技能溢价；
- 有记录的津贴、轮班或关键人才安排。

关注同岗薪酬差异、相邻职级重叠、上下级倒挂、新老员工倒挂、绩效薪酬区分，以及同职级跨部门差异。

存在差异不等于不公平。先验证比较对象是否有效，并检查合理解释变量能否解释差异。

## Step 5：诊断外部竞争力

只有实际取得相关、有效的市场薪酬数据后，才能判断外部竞争力。至少检查：

- 行业、地区、企业规模、岗位和职级是否匹配；
- 调研生效日期、薪酬定义、样本质量和币种；
- 相关市场分位值和企业既定薪酬定位；
- 人才稀缺或溢价条件是否导致基准不可比。

没有真实市场数据时，明确说明：“目前无法判断外部竞争力，需要匹配行业、地区、企业规模、岗位、职级和统计口径的外部薪酬基准数据。”不得写“低于市场”“高于市场”或“低于行业平均”。

## Step 6：诊断薪酬压缩和倒挂

在确认比较对象有效前，把压缩和倒挂作为 HYPOTHESIS。

解释疑似情况前，检查岗位、职级、职责范围、地区、绩效、入职时间、调薪记录、特殊津贴、稀缺技能溢价和用工安排。区分：

- **薪酬压缩**：可比相邻群体之间的薪酬区分度较小；
- **薪酬倒挂**：在选定薪酬口径下，较低职级、下级或较新的可比对象薪酬更高。

没有企业薪酬政策、薪酬带宽、外部基准或经批准的判断规则时，不自行设定压缩阈值，也不定义何种差距属于“异常”。

## Step 7：诊断薪酬结构

明确适用的薪酬组成：

- Base Pay｜固定工资；
- Variable Pay｜浮动薪酬；
- Bonus｜奖金；
- Allowance｜津贴；
- Total Cash｜总现金收入。

检查结构是否与岗位性质相匹配，浮动薪酬是否具有真实绩效依据，规则是否可理解，以及不同岗位是否被不恰当地套用同一激励机制。没有岗位、战略、风险、市场和支付能力证据时，不判断固定与浮动比例“正确”或“不正确”。

## Step 8：使用已有 Analysis Tools

只使用项目当前实际注册的 Tool：

- `read_excel_metadata`：核对 Sheet、字段、类型、缺失和脱敏预览；不做薪酬分析；
- `analyze_compensation_summary`：计算整体或允许分组下的 count、mean、median、min、max；
- `analyze_missing_data`：判断诊断所需字段的完整程度；
- `calculate_headcount`：在需要时确认总体和分组样本量；
- `analyze_performance_summary`：仅在验证绩效薪酬假设时描述群体绩效，不证明因果；
- 离职相关 Tool：仅当问题包含离职统计或离职率，并且人数口径充分时使用。

不得根据 Excel preview 计算，也不得让语言模型复算 Tool 指标。`analyze_compensation_summary` 不能识别薪酬倒挂、计算薪酬带宽、判断公平性或评估市场竞争力。

如果未来确已注册 `calculate_compa_ratio`、`detect_salary_inversion`、`analyze_pay_band` 或 `calculate_range_penetration`，再优先使用相应 Tool。仅在本 Skill 中出现这些名称，不代表它们目前存在。

## Step 9：确定优先假设

选择与当前证据最相关的 2—4 个假设，不输出冗长通用清单。每个假设都要记录：

- **已有证据**：当前支持它的 FACT、DATA_FACT 或 DOCUMENT_FACT；
- **缺失或反向证据**：可能削弱该假设的信息；
- **验证方法**：所需比较、Tool 结果、记录核查、访谈或文件；
- **决策含义**：假设得到验证后，什么行动才变得合理。

常见假设包括岗位价值与薪酬错配、新员工市场定薪上涨快于内部调薪、缺少薪酬带宽治理、例外审批不一致、绩效结果未有效传导到薪酬。只在与当前问题相关时使用。

## Step 10：让证据匹配诊断问题

| 诊断问题 | 最低证据 |
|---|---|
| 内部公平性 | 岗位、职级、统一薪酬口径、职责范围、任职时间、绩效 |
| 外部竞争力 | 有效外部市场数据，以及行业、地区、规模、岗位、职级和生效日期 |
| 薪酬倒挂 | 岗位、职级、汇报关系或比较群体、入职时间、薪酬、调薪记录、已记录溢价 |
| 绩效薪酬联动 | 口径一致的绩效结果、奖金或调薪结果、发生时间、政策与执行记录 |
| 薪酬结构 | 薪酬组成定义、适用对象、岗位类型、目标比例、发放规则和实际结果 |

最低证据缺失时，保持 HYPOTHESIS，将证据收集作为下一步行动。

## Step 11：形成分层建议

建议强度必须与证据强度匹配：

- **Immediate｜短期控制**：暂停缺少依据的非标准例外审批并核查事实；不得影响合同或法定应付薪酬；
- **Diagnostic｜诊断**：统一口径、匹配可比岗位和职级、核对缺失、调用已有统计工具、复核例外；
- **Structural｜结构改善**：证据确认后再设计或修订岗位体系、职级、薪酬带宽、晋升调薪和分类激励；
- **Governance｜治理**：建立调薪标准、例外审批、记录、沟通、年度复盘和结果监控。

信息不足时优先诊断，不直接建议全员涨薪、大规模降薪、立即调整个人工资或认定某位员工“工资过高”。

## 决策边界

不得直接决定谁应涨薪、降薪、晋升、辞退或具体调整多少，也不得根据描述性统计认定某人薪酬过高或绩效差。

可以提供已验证的分析结果、决策条件、方案框架和复核顺序；只有区间具有明确有效依据时才可提供建议区间。最终薪酬决定由获授权的企业管理者依据合同、制度、审批、预算和当地法律完成。

## 输出规则

正式 HR 诊断继续严格使用项目统一的五部分结构：

1. `# 问题判断`
2. `# 可能原因`
3. `# 需要补充的信息`
4. `# 建议措施`
5. `# 下一步行动`

用这五部分呈现诊断对象、优先假设、缺失证据、分层建议和验证行动。不得因为使用 Skill 增加新的一级标题。纯 Tool 元数据或计算回复继续沿用项目已有 Tool 输出协议。

## 失败处理

- **数据缺失**：说明缺什么、阻断什么结论、最小收集动作是什么；不自行填补；
- **比较无效**：停止比较，说明不一致的范围或薪酬口径；
- **Tool 失败**：呈现真实错误，不声称分析成功；
- **没有市场数据**：停止形成竞争力结论；
- **样本过小**：说明限制，不推广为部门或企业结论；
- **证据冲突**：列出冲突和验证方式，不静默选择来源；
- **敏感明细**：先最小化、聚合或要求匿名化。

## 完成标准

输出前确认：

1. 已明确用户真正的薪酬问题；
2. 已定义分析范围和比较口径；
3. 已区分事实、主张、数据事实、假设和建议；
4. 已识别会改变决策的数据缺口；
5. 必要计算使用实际可用 Tool，没有重复实现计算；
6. 原因诊断包含 2—4 个优先假设；
7. 每个优先假设都有验证方法；
8. 建议强度与证据强度匹配；
9. 没有把差异直接等同于不公平；
10. 没有在缺少真实市场数据时判断市场竞争力；
11. 没有自动作出具体个人薪酬决定；
12. 保持固定五部分输出协议。
